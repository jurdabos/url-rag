## [Unreleased]
### Changed
- `dags/ingestionrag.py`: `fetch_documents` separates `FETCH_ERRORS`, the failures a link can cause by itself, from anything else, which points at a bug. Neither stops the batch, because pages from the web must not be able to block an unattended ingest, but a bug no longer poses as a bad link. The run reports pre-filter skips and fetch failures as counts by reason, and fails when every URL fails, because that is an outage. Fetching and retries move to `include/ingest.py`, where they can be unit tested, and tasks import it lazily to keep DAG parsing light.
- `dags/ingestionrag.py`: adds `report_unexpected_failures`, which emails one digest per run, grouped by exception, to the address in the `rag_alert_email` Variable through the `smtp_default` connection. The digest lists hosts and masks URLs, because it leaves the stack; full URLs stay in the task log. The task is a parallel branch off `fetch_documents`, because Airflow derives a run's state from its final tasks: placed after the upsert, a successful email would turn a failed run green, even as a teardown. A broken mail setup fails the run without blocking the ingest, and a run with nothing to report does not touch SMTP.
- `scripts/set_smtp_connection.sh`: loads `smtp_default` from the WSL keyring into Airflow's encrypted connection store, so the Gmail app password never sits in a plain `.env` file, and sends a test email. Containers cannot reach the keyring, so rerun it after `astro dev kill`, which wipes Airflow's database.
- `Dockerfile`: moves the base image from `runtime:3.0-14` (Airflow 3.0.6) to `runtime:3.3-2-python-3.13` (Airflow 3.3.0), matching `apache-airflow>=3.3.0` in `pyproject.toml`. The dependency floors were solved against 3.3 but installed onto 3.0.6, so a rebuild broke the stack in stages: `fastapi` 0.162 could not import `cadwyn` 5.6.2, PyJWT 2.12+ rejected the unset JWT issuer on every API request, and with those patched the execution API answered 422 when a task started. The 3.3 runtime needs no pins or workarounds, and the plain `3.3-2` tag is avoided because it ships Python 3.14, outside `requires-python`.
- Local stack: Airflow 3.3 cannot migrate a metadata database on the Astro CLI's default Postgres 12.6, because a migration calls `gen_random_uuid()`, which needs Postgres 13. Existing local stacks need `astro config set postgres.tag 16` and a fresh database through `astro dev kill`. Only the `rag_content_hashes` Variable has to be carried across: without it, the next run cannot tell which URLs to purge from Pinecone.
- `include/url_filter.py` (moved from `src/url_rag/url_filter.py`) gains `clean_url` and `clean_urls`, and `dags/ingestionrag.py` applies them at load, so fetches, logs, Pinecone IDs and metadata only see cleaned URLs. Userinfo, fragments and every query parameter outside the `DEFAULT_KEEP_PARAMS` allowlist are dropped, and a kept value must be short and not an email address; a blocklist cannot keep up with tracking and session parameters. URLs that differ only in dropped parts collapse into one. The next run treats changed URL strings as removed and new, so it re-embeds those pages and purges their old vectors.
- `should_skip_url` also rejects private addresses, Google Search, sharing services, personal-account services and paths carrying an opaque token. `sharepoint.com` and `cloud.databricks.com` are matched as whole suffixes, so every tenant and workspace is covered.
- `.dockerignore`: excludes `include/urls.json`, so the runtime's ONBUILD `COPY . .` no longer bakes the list into built images. Local development is unaffected, because `astro dev` mounts `include/`. A deployed image falls back to the demo list unless the `rag_source_urls` Airflow Variable is set.
- `.github/workflows/lint.yml`, `.gitleaks.toml`: the gitleaks job checks its download against a pinned SHA-256 and runs `gitleaks git`, because `detect` is deprecated. Docs and changelogs are scanned now; false positives go in `.gitleaksignore`.
- Adopted the canonical non-truncating CLI help from acidbase: the top-level command group is now built with `acidbase.cli_utils.group` (a `click.Group` subclass) instead of `click.group`. Click's default group listing truncates each command's short help at 45 characters, so longer descriptions ended in `...`; the shared group wraps the full first paragraph onto aligned continuation lines instead. `RichGroup.main` also routes output through `ensure_unicode_safe_streams()`, so non-ASCII help (em dashes, accented words) survives on Windows consoles using a legacy code page. `uv.lock` pins acidbase at the commit providing `cli_utils`.
### Fixed
- **Pages with an empty `<title>` are no longer lost as failed links.** `soup.title.string` is `None` for an empty title, and the crash was caught by a broad `except Exception` and logged as a bad link. `include/ingest.py` now falls back to the URL as the title.
- **The ingestion DAG no longer skips failed batches and goes green.** `generate_embeddings` and `upsert_to_pinecone` logged a batch that kept failing, then carried on, so old vectors could be purged with nothing replacing them while the manifest recorded those pages as done. `with_retries` in `include/ingest.py` always raises on its last attempt, and `chunks_skipped` is gone from the task result.
- **A failure to read the hash manifest no longer passes for a first run.** A broad `except` treated any error as a missing manifest, which would have orphaned every removed URL. Only a missing Variable now counts as a first run.
- **Purging stale vectors works again, and can no longer fail silently.** Newer Pinecone clients yield `ListItem` objects from `index.list`, which `index.delete` rejects, so `upsert_to_pinecone` deleted nothing. It only logged those errors, reported success, and saved the new hash manifest, which dropped the URLs still awaiting a purge. `include/url_filter.py` adds `vector_ids`, deletes go out in batches of at most 1,000 IDs, and any purge failure now stops the task before the manifest is saved.
- **`upsert_to_pinecone` no longer fails on `ModuleNotFoundError: ijson`.** The task imports `ijson`, which no dependency list declared, so the image lacked it and each run embedded every changed page before failing, leaving stale vectors in place and the hash manifest unsaved. `pyproject.toml` and `requirements.txt` now declare it. The error only surfaced at run time because task-level imports are not evaluated when a DAG is parsed.
- `plugins/url_helpers_plugin.py` imported `url_rag.url_filter`, which the Airflow image does not contain because `.dockerignore` excludes `src/`. The plugin now imports `include.url_filter`, and `dags/ingestionrag.py` drops its private copies of the skip lists, so one module serves the DAG, the plugin and the tests.
- `.python-version` (3.13), `.gitignore`, `.github/workflows/lint.yml`: CI now runs on a deliberately
  pinned Python. `.gitignore` no longer ignores `.python-version` (a rule inherited from the old acidbase
  template), so the pin is tracked; without it the lint job's bare `uv python install` picked the newest CPython
  (3.15 broke bpmfinder via numba). The lint job now fails with a clear annotation when the file is missing, and
  syncs with plain `uv sync --frozen` instead of the always-failing `--extra dev` fallback.
- **Docker image build (`astro dev start`) no longer fails on `apt-get update: Permission denied`.** The Dockerfile previously carried explicit `COPY packages.txt . / RUN apt-get update ...` and `COPY requirements.txt . / RUN pip install ...` blocks as "explicit reinforcements" of the runtime's ONBUILD chain. But the ONBUILD chain ends with `COPY --chown=astro:0 . .`, which drops the working directory to the unprivileged `astro` user; any apt invocation after that fails with `E: List directory /var/lib/apt/lists/partial is missing. - Acquire (13: Permission denied)`. The blocks were also pure noise — the ONBUILD steps already installed everything as root. Removed them; the Dockerfile is now just `FROM ...` plus a comment block describing the ONBUILD contract and the project's conventions for `packages.txt` / `requirements.txt`.
- **Docker image build (`astro dev start`) no longer fails on `Git executable not found`.** The Astronomer Runtime base image does not ship `git`, but uv needs it inside the container to clone the `acidbase` `git+https://...` dependency declared in `requirements.txt`. Added `git` to `packages.txt` so the runtime's ONBUILD `install-system-packages` step `apt`-installs it **before** `install-python-dependencies` runs. Dockerfile comment updated to document the dependency.
- **Docker image build (`astro dev start`) no longer fails on `acidbase==0.1.0 depends on Python>=3.13`.** The Astronomer Runtime base image ships Python 3.12.12, but `acidbase` declared `requires-python = ">=3.13"` (an oversight — the source already targets `py312` for ruff and uses no 3.13-only features) and `url-rag` itself declared `requires-python = ">=3.13,<3.14"`. Fixed at both ends:
  - `acidbase` v0.1.1 now declares `requires-python = ">=3.12"`; uv.lock is updated to pin the new public-mirror commit (`3685c654`).
  - `url-rag` lowered to `requires-python = ">=3.12,<3.14"` and `[tool.ruff].target-version = "py312"`.
- **Docker image build (`astro dev start`) no longer fails on `apache-airflow` from `requirements.txt`.** The Astronomer Runtime base image (`astrocrpublic.azurecr.io/runtime:3.0-14`) ships Airflow itself and its ONBUILD `install-python-dependencies` step rejects any `apache-airflow` pin in `requirements.txt`. `requirements.txt` had previously been generated by `uv export --frozen` which inlined `apache-airflow==3.0.6`, breaking the build.
- **`url-rag push` no longer strands already-committed work with a misleading "Nothing to push".** Bumped the pinned `acidbase` commit in `uv.lock` from `3685c654` to `c3bc109` (public mirror) to pick up `acidbase`'s new `_count_unpushed()` guard in `run_push`: when the working tree is clean **but** local commits are ahead of the upstream, the wrapper now pushes the committed work instead of short-circuiting. Earlier the clean-tree check returned `rc=0` with "Nothing to push — working tree is clean", silently leaving committed security bumps unpushed. Pure lockfile bump; `pyproject.toml` and `requirements.txt` (no SHA pin) are unchanged.
### Added
- `scripts/sync_requirements.py` (stdlib-only): regenerates `requirements.txt` from `pyproject.toml`'s `[project].dependencies`, dropping the Airflow core packages (`apache-airflow`, `apache-airflow-core`, `apache-airflow-task-sdk`). Exits non-zero on rewrite so pre-commit surfaces drift.
- Local pre-commit hook `sync-requirements` wired in `.pre-commit-config.yaml`, triggered on changes to `pyproject.toml`, the script itself, or `requirements.txt`.
- Dockerfile header comment documenting the ONBUILD triggers shipped by the Astro Runtime image and why our explicit `COPY`/`RUN` lines are intentional reinforcements rather than the primary install step.
- README "Dependency management & Astro image build" subsection explaining the intentional pyproject.toml ↔ requirements.txt divergence and the sync workflow.
